芯片模型展开时，最直观的是几块薄片依次抬起来。看着它，很自然会问：哪层是 CPU，哪层是 TEE，Android 又在哪里？

这个问法需要转一下方向。模型展开的是物理结构，软件的运行环境并不按薄片分层。先弄清楚一个接点如何从晶粒走到主板，后面的权限问题才有合适的位置。

这里的模型是概念视图，不对应具体产品的剖面或比例。它能帮我们辨认关系，不能用来读真实芯片的布局。

## 从最下面的接点往上看

与其先记几个英文名字，不如沿连接往回走。以基板式倒装封装为例，主板焊盘接到封装底部的焊球，基板里的布线再把它引向晶粒侧的凸点。晶粒上的电路由此与外部供电、信号和其他器件连接。

```text
主板焊盘 → 封装焊球 → 基板布线 → 晶粒凸点 → 晶粒电路
```

这条线只画连接关系，没有画电源网络、材料厚度或真实走线。Amkor 的 [fcCSP 资料](https://amkor.com/packaging/laminate/fccsp/)展示了这类倒装互连的封装方案。另一些封装使用键合线：线从晶粒接点接向载体，形态与倒装凸点不同。

现在再看模型里那块画着线路的薄板：它更适合提示基板的布线，而不是表示某个程序的控制流。基板要把很密的内部接点引向外部可连接的位置。它仍属于封装内部，和手机主板不是同一块板。

如果把这条路径反过来理解，晶粒才是电路真正所在的地方。封装负责让这块小而脆的电路成为能装到产品里的器件；它既要连接，也要支撑、保护和处理热的问题。

## 那块盖子为什么最抢眼

爆炸视图需要一个容易辨认的外形，所以模型用顶盖表达外部保护与散热。可这里的 Package 标签应理解为整个封装，不能只理解成盖子。

实际封装可能采用塑封材料，也可能有不同散热结构，甚至看不到模型里这样的独立金属盖。看到模型上的银色表面，不宜反推某款手机 SoC 也有相同构造。

[TI 的装配与测试介绍](https://www.ti.com/about-ti/worldwide-manufacturing/assembly-test.html)把晶圆切割、晶粒安装、互连和封装放在制造流程中说明。把它和模型一起看，会更容易理解：晶圆上的电路完成后，还要经过一系列装配与测试，才成为手上那颗带型号标识的器件。

所以，拿到一张芯片外观照片时，首先看到的常常是封装表面。文字标记、尺寸和接点形式有用，但它们还不是内部电路的照片。

## 一颗器件，里面未必只有一块晶粒

日常说“一颗芯片”，常常指一颗封装好的器件；说 die，则是在说其中的晶粒。两个计数口径不一定相同。多晶粒、堆叠和不同集成方式，会让一颗器件包含不止一块晶粒。

专题采用了容易阅读的简化结构。我不想继续往里面叠更多矩形来假装接近某款真芯片：多放一片，在视觉上很便宜，在物理意义上却需要说明它是什么、如何连接、热从哪里走。

同样，die 上画出的矩形只是功能分区的提示。没有产品架构图或有来源的版图分析，就没有依据说“这个位置是四个 CPU 核，那个位置是安全核”。逻辑模块的名字和照片上的几何形状之间，还隔着真实设计资料。

## 连得上，为什么还会读不到

物理互连解释信号能走到哪里。软件更关心：一个访问请求到达资源时，是否被允许完成。

设想 CPU 和某个外设都连接到内存控制器。两条路径在物理上存在，不代表两者拥有相同权限。CPU 的地址转换、设备侧的转换，以及平台资源访问控制，可以分别参与判断。详细的访问路径放在[内存与 DMA 那篇](/posts/chip-memory-isolation/)里展开。

反过来，两个软件环境共享一块晶粒，也不意味着它们共享所有内存。TEE 是执行与隔离关系，不能贴在模型的一层薄板上；XBL 是启动软件，也不是某层基板的名字。

这正是我希望这个模型带来的阅读入口：先从可见的结构认识器件，再换一张权限图理解软件。把两张图强行合在一起，会很像解释清楚了，实际上只是在给薄片起名字。
