Android 上 arm64-v8a 已经是绝对主流，`libxxx.so` 拖进 IDA 之后看到的就是 AArch64 汇编。这篇整理 AAPCS64 里对逆向最有用的那部分。

## 寄存器分工

64 位下有 31 个通用寄存器，`x0`–`x30`。同一个寄存器用 `w` 前缀访问就是低 32 位，比如 `w0` 是 `x0` 的低半部分。

| 寄存器 | 用途 | 谁负责保存 |
| --- | --- | --- |
| `x0`–`x7` | 前 8 个整型参数 / 返回值 | 调用者 |
| `x8` | 间接返回地址（大结构体返回） | 调用者 |
| `x9`–`x15` | 临时寄存器 | 调用者 |
| `x16`/`x17` | IP0/IP1，链接器跳板会用 | 调用者 |
| `x18` | 平台寄存器，Android 上是 SCS | 保留 |
| `x19`–`x28` | 被调用者保存 | 被调用者 |
| `x29` | FP，帧指针 | 被调用者 |
| `x30` | LR，返回地址 | 被调用者 |
| `sp` | 栈指针，必须 16 字节对齐 | — |

浮点和向量参数走 `v0`–`v7`，返回值也在 `v0`。

**对逆向最直接的用处**：看函数开头连续读了 `x0`、`x1`、`x2`，就知道至少三个参数。JNI 函数还要额外记住，`x0` 恒定是 `JNIEnv*`，`x1` 是 `jobject` 或 `jclass`，真正的第一个 Java 参数从 `x2` 开始。

## 标准的函数序言

绝大多数非叶子函数长这样：

```armasm title="函数序言" {1,2,3}
stp     x29, x30, [sp, #-0x30]!
mov     x29, sp
stp     x19, x20, [sp, #0x10]
str     x21, [sp, #0x20]
```

逐条看：

- `stp x29, x30, [sp, #-0x30]!` —— 一次压两个寄存器。末尾的 `!` 是 pre-index，先把 `sp` 减 `0x30` 再存，等于同时开辟了 0x30 字节的栈帧
- `mov x29, sp` —— 帧指针指向当前栈顶，后面所有局部变量都相对 `x29` 寻址
- 后面几条保存 `x19` 以上的寄存器，说明函数内部要用它们存长期存活的值

尾声是对称的：

```armasm title="函数尾声"
ldr     x21, [sp, #0x20]
ldp     x19, x20, [sp, #0x10]
ldp     x29, x30, [sp], #0x30
ret
```

这里的 `[sp], #0x30` 是 post-index，先按 `sp` 取值再把 `sp` 加回去。`ret` 默认跳到 `x30`。

**看栈帧大小最快的办法就是看第一条 `stp` 的立即数。** 上面这个函数栈帧是 0x30 字节。

## 叶子函数会省掉一切

不调用其他函数的叶子函数，不需要保存 `x30`，往往连栈都不开：

```armasm title="一个典型的叶子函数"
    lsl     w8, w0, #2
    add     w8, w8, w1
    eor     w0, w8, #0x5a
    ret
```

看到没有 `stp x29, x30` 就基本可以断定是叶子函数，逻辑通常很短，适合优先分析。

## 参数超过 8 个怎么办

前 8 个走寄存器，剩下的从右往左压栈。所以第 9 个参数在 `[sp]`，第 10 个在 `[sp, #8]`。在 IDA 里如果看到函数里读 `[x29, #0x40]` 这种正偏移（大于栈帧大小的部分），大概率就是在取第 9 个及以后的参数。

## PAC：新设备上多出来的指令

Android 12 以后的部分设备开启了指针认证，函数头尾会多出这两条：

```armasm
paciasp
...
autiasp
ret
```

`paciasp` 用栈指针作上下文给 `x30` 加签名，`autiasp` 在返回前验证。分析时可以当成 nop 忽略，但**如果要 patch 或者 hook 返回地址，必须处理它们**，否则验证失败会直接 crash。有些编译器会把 `autiasp; ret` 合并成一条 `retaa`。

## 一个完整的例子

把上面的规则套到一个真实形态的 JNI 函数上：

```armasm title="Java_com_example_Native_check" {1,2,6,7,12}
    stp     x29, x30, [sp, #-0x20]!
    mov     x29, sp
    stp     x19, x20, [sp, #0x10]

    mov     x19, x0                  ; x19 = JNIEnv*
    mov     x20, x2                  ; x20 = 第一个 Java 参数 (jstring)

    ldr     x8, [x19]                ; 取 JNIEnv 的函数表
    ldr     x8, [x8, #0x538]         ; GetStringUTFChars 的偏移
    mov     x0, x19
    mov     x1, x20
    mov     x2, xzr
    blr     x8                       ; 调用

    ; x0 现在是 const char*
    bl      validate

    ldp     x19, x20, [sp, #0x10]
    ldp     x29, x30, [sp], #0x20
    ret
```

关键点在 `ldr x8, [x8, #0x538]` 这类**通过偏移调用 JNIEnv 函数表**的模式。`0x538` 在 arm64 上对应 `GetStringUTFChars`。IDA 里导入 `jni.h` 并把 `x19` 的类型设成 `JNIEnv*`，这些偏移就会自动变成可读的函数名，效率提升非常明显。

## 小结

分析一个陌生 so 函数，按这个顺序看最快：

1. 有没有 `stp x29, x30` — 判断叶子 / 非叶子
2. 第一条 `stp` 的立即数 — 栈帧大小
3. 函数开头读了哪几个 `x0`–`x7` — 参数个数
4. 保存了哪些 `x19`+ — 内部有几个长期变量
5. 所有 `bl` / `blr` — 调用了什么
